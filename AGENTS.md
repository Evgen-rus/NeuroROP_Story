# AGENTS.md — NeuroROP Story

## Миссия
Собрать отдельную интерактивную презентацию НейроРОПа в формате premium scrollytelling. Цель — за 5–7 минут дать директору/собственнику и РОПу понять продукт без длинного текста.

Это НЕ production Neuro_rop_practice. Не подключать его backend, Bitrix, SQLite, webhooks, OpenAI API, секреты или реальные CRM-данные. В проекте только синтетические/анонимизированные данные.

## Оркестрация моделей
Primary/lead: **GPT-5.6 Sol, Medium**. Он принимает продуктовые и архитектурные решения, интегрирует изменения и делает финальную приёмку.

Workers:
- **Luna High** — основная bounded-реализация сцены/компонента, визуальная проработка, локальный debugging.
- **Luna Max / Extra High**, только если реально доступно в Codex — сложная локальная анимация, тяжёлый визуальный баг, нетривиальная оптимизация. Не использовать для рутины.
- **Luna Low/Medium** — scouting, поиск usages, простые тесты, доступность, CSS cleanup, проверки.
- read-only `code_mapper`/scout, если доступен — только карта файлов/символов; без архитектурных решений и без редактирования.

Правила:
- По умолчанию lead + максимум 2 workers параллельно; максимум 1 worker верхнего reasoning-уровня.
- Не запускать несколько Sol/Astra/lead-агентов.
- Worker не запускает других workers без решения lead.
- Один владелец записи на файл.
- Если задача мала, lead делает сам — не делегировать ради делегирования.
- Перед делегированием передать только цель, scope, ограничения, expected output и проверки.
- Архитектура, storyboard, продуктовый смысл и финальная приёмка остаются у lead.

## Контекст-эффективность
- Не читать все reference screenshots каждый раз. Сначала `docs/06_PRIVACY_AND_ASSETS.md`, затем только нужный файл.
- Не читать весь проект, если известен компонент/сцена.
- После worker lead проверяет diff и критические места самостоятельно.
- Не дублировать одну и ту же реализацию разными агентами.

## Продуктовые инварианты
Нельзя менять без явного решения пользователя:
- аудитория: директор/собственник + РОП;
- формат: 5–7 минут, desktop-first, 80% guided scroll / 20% interaction;
- центральная механика: **вся команда → менеджер → одна сделка → решение → помощь РОПу → помощь менеджеру → feedback loop**;
- главный тезис: **«CRM хранит события. НейроРОП превращает их в решение.»**
- НейроРОП — один интеллект, два уровня помощи: РОП и менеджер;
- Quick Help/«Дожим» использует контекст сделки и лучшие практики продаж;
- не продавать «AI ради AI»;
- не показывать внутренние модели, FULL/MINI, routing, Terra/Luna и техническую кухню;
- финальная CTA: **«Запустить пилот»**.

## Design invariants
- Светлый спокойный research/product style, много воздуха.
- Визуальный язык реального НейроРОПа: белые карточки, тонкие границы, синий акцент, красный/жёлтый/зелёный только по смыслу.
- Не копировать Anthropic буквально: перенимаем scrollytelling и ритм, не фирменные формы/цвета.
- Одна мысль на экран.
- 60% реальный UI / 40% абстрактная графика.
- Никаких декоративных 3D, «AI-сфер», неоновых сеток и бессмысленных частиц.
- Анимация должна объяснять мысль.
- Mobile допустимо упрощать, desktop — эталон.
- Обязателен `prefers-reduced-motion`.

## Privacy
`references/raw/` содержит исходные пользовательские скриншоты с реальными названиями и именами. Они:
- только для локального анализа Codex;
- не импортируются приложением;
- не копируются в `public/`, `src/assets/`, build или deploy;
- не публикуются в README/issue/PR;
- при реконструкции UI заменять компании и ФИО синтетическими значениями.

Разрешено сохранять реальные агрегированные числа, если они уже одобрены в storyboard (например 34 / 24 / 6 / 4).

## Проверки
После frontend-изменений:
1. `npm run typecheck`
2. `npm run build`
3. визуальный smoke desktop 1440–1920 px
4. visual smoke mobile ~390 px
5. проверить keyboard/navigation и `prefers-reduced-motion`
6. проверить, что `references/raw` не попадает в build.

Не называть работу завершённой, если не выполнены доступные проверки.

## Handoff worker → lead
Коротко:
FINDINGS: факты с path
CHANGES: что изменено
FILES: список
RISKS: риски/none
VERIFICATION: команды и результат

## Что агент может решать сам
Можно:
- декомпозировать компоненты;
- оптимизировать animation implementation;
- выбирать SVG/CSS технику;
- улучшать responsive;
- добавлять локальные тесты;
- рефакторить без изменения продуктового смысла.

Нельзя без согласования:
- менять порядок/смысл сцен;
- добавлять функции НейроРОПа, которых нет в продукте;
- менять главный месседж;
- добавлять backend/CRM/API;
- публиковать сырые скриншоты;
- делать визуальный редизайн, противоречащий design spec.
